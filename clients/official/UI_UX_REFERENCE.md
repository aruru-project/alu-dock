## 1. 文档目的

本文保留早期 UI/UX 调研和 Android 适配思路，方便追溯取舍；它不是 PRD，也不是当前实现清单。当前客户端已经确定采用 Tauri 2 + Vue，并先完成 Linux 上的 Rails WebConsole Worker 界面移植，再复用到 Android。

当前通用客户端与 Rails 专用界面的已确认差异包括：使用原生文件“附件”而非图片/Studio 图库；不生成、发送或解析阿露专用的消息时间尾巴；不继承固定 `alu` Work、Alu Workstation 路径及 Rails 本地媒体运输。正常消息时间仍来自消息记录自身的时间戳。

以下内容仅在没有更高权威实现或文档与之冲突时作为背景参考：

- 客户端以可安装 APK 形态交付。表现层技术待定，可以采用 Android 原生 UI，也可以采用 Tauri 2 / WebView 等跨平台方案；无论选型，UI 与样式都应尽量延续当前 WebConsole。
- 本文只沉淀 UI、交互和功能取舍，不重复 AluDock 对接文档。
- New Work 改用新版 AluDock 提供的目录浏览，不继承固定或默认工作目录。
- Tree 等复杂界面必须采用适合触控与图形客户端的交互，不能受 TUI 纯键盘模式限制。

本文使用以下约束词：

- **必须**：已确认的产品方向，或这项能力一旦纳入客户端就必须遵守的体验约束；不自动代表首版排期。
- **建议**：推荐的 Android 体验，后续可在原型阶段调整。
- **待定**：需要结合首版范围或 AluDock 能力再次确认。

## 2. 产品定位

一句话定义：

> 一个保留 Alu WebConsole 气质、触控优先、能充分利用手机、平板与折叠屏的 AluDock Android 图形客户端。

### 2.1 必须保持的部分

- 深蓝星空、樱花粉主强调色、冰蓝辅助色构成的“阿露终端”视觉身份。
- 以 Work 为一级导航对象、以 Session 对话为主工作面的信息架构。
- 对话、运行过程、工具调用、Queue、连接状态和错误状态之间清晰的视觉层级。
- WebConsole 已有的移动端紧凑形态，以及宽屏上更舒展的控制和信息展示。
- 所有主要操作都能通过点击或触摸完成；键盘快捷键只能作为增强方式。

### 2.2 Android 端自主决定的部分

- 原生导航、返回手势、系统栏、软键盘、文件选择器、通知和生命周期处理。
- Android 内部架构、组件体系、状态管理和渲染方案。
- 在不改变产品气质的前提下，使用更适合触控、鼠标和大屏的交互方式。

### 2.3 本文不覆盖

- TLS、证书 Pinning、端口和认证的底层实现；但配对、地址录入、Host 管理及其用户反馈属于本文必须覆盖的产品体验。
- AluDock 协议、请求字段、事件格式和错误码映射。
- Android 技术选型、模块拆分、数据层或缓存设计。
- 工期、版本排期和发布方式。

上述底层内容以 AluDock 与 Android 项目各自的技术文档为准。界面向普通用户说明连接步骤和操作结果，证书、指纹和 transport 等内部概念留在工程诊断中。

## 3. 核心体验原则

### 3.1 看起来仍然是 Alu WebConsole

导航栏、对话气泡、状态点、选择器、命令中心、弹窗和工作列表应延续现有 WebConsole 的形状、密度和色彩关系，让熟悉 WebConsole 的用户可以立即辨认。定制组件外观时同时处理这些要素，而不只替换框架默认颜色。

返回、触控、软键盘、无障碍和窗口适配遵循 Android 平台规范，组件外观保留品牌视觉。

### 3.2 触控优先，键鼠增强

- 手机上不得存在只能依靠快捷键、方向键或命令文本才能触发的核心功能。
- 平板和折叠屏应支持鼠标悬停、滚轮、右键以及外接键盘焦点导航。
- 快捷键可以提高效率，但界面中必须始终存在可发现的可视入口。
- 长按和手势不能成为唯一入口；重要动作仍需按钮、菜单或明确的操作区。

### 3.3 对话是主工作面

用户消息、Assistant 回复、thinking、工具、运行通知和错误各自使用稳定的组件，按内容类型形成清晰层级。长内容应可展开、复制、预览和定位。

### 3.4 状态与实际结果一致

- “正在连接”“正在恢复”“已离线”“操作结果待确认”必须区分。
- 临时断线不应清空当前对话、草稿、滚动位置或已打开的浏览上下文。
- 操作提交期间阻止重复点击；结果未确认时不能提前显示成功。
- 后台恢复应尽量无打扰，确实需要用户介入时再给出明确动作。

### 3.5 利用大屏空间

平板、横屏和折叠屏应利用额外宽度展示完整身份、统计和操作，并让 Tree、目录浏览器或详情形成更高效的宽屏工作面。主对话延续当前 WebConsole 的完整可用宽度与稳定边距；Dialog、选择器和详情面板按内容设置合理宽度。

### 3.6 保留用户上下文

旋转屏幕、改变窗口大小、开合折叠屏、关闭再打开底部面板时，应尽量保留：

- 当前 Work 与 Session。
- 对话滚动位置和是否跟随最新消息。
- 未发送草稿与附件选择。
- Tree 的展开、筛选、搜索和当前选中节点。
- 命令或弹窗中尚未提交的输入。

## 4. 视觉语言

### 4.1 参考色彩

以下颜色来自现有 WebConsole，作为 Android 视觉基线；最终应通过设计 Token 统一维护。

| 语义 | 参考色 | 用途 |
|---|---:|---|
| 深空背景 | `#080C18` | 全局背景 |
| 抬升背景 | `#0E1220` | 弹窗、面板 |
| Surface | `#111828` | 输入框、卡片 |
| Hover / Pressed | `#1A2236` | 悬停、按压、选择反馈 |
| 主文字 | `#DCE8F4` | 正文与主要标题 |
| 次文字 | `#8898B0` | 说明与元信息 |
| 弱文字 | `#505A6A` | 占位、低优先级状态 |
| 樱花粉 | `#F472B6` | 品牌主强调、主要选择态 |
| 冰蓝 | `#7EC8E0` | 链接、辅助动作、信息状态 |
| 琥珀 | `#FBBF24` | thinking、工具、等待和警告 |
| 红色 | `#F87171` | 错误、危险操作 |
| 薄荷绿 | `#34D399` | 已连接、运行正常 |

背景建议保留非常克制的星点或深空渐变。星点只负责品牌氛围，不应降低文字对比度，也不应持续进行高耗电动画。

### 4.2 字体与信息密度

- 整体继续采用等宽字体气质，优先考虑 JetBrains Mono 或视觉接近的可用字体。
- 对话正文以约 `14sp` 的紧凑密度为参考；辅助信息约 `10–12sp`。
- 用户开启系统大字体后允许组件增高、换行和重排，不允许裁切关键操作。
- 代码块必须使用等宽字体；长行横向滚动，不强制压缩到不可读。
- 数字统计使用等宽数字，避免流式更新时界面左右跳动。

### 4.3 形状与层级

- 普通按钮和选项使用约 `7–10dp` 圆角。
- 对话气泡和弹窗使用约 `12–17dp` 圆角。
- Composer 延续更饱满的胶囊形态，约 `16–20dp` 圆角。
- Assistant 气泡保留左上角较直、用户气泡保留右下角较直的方向感。
- 边框优先于大面积阴影；粉色或蓝色光晕只用于焦点和关键状态。
- 危险动作不得只靠颜色区分，还需图标、文案或确认步骤。

### 4.4 动效

- 面板进入、消息出现和状态切换保持轻量，参考时长 `140–250ms`。
- Agent 正在响应时可使用粉色环形进度提示，但不能代替连接状态。
- 遵循系统“减少动态效果”设置；关闭浮动、缩放等非必要动画。
- 流式正文更新不做逐字弹跳或反复淡入，避免长会话产生视觉噪声。

## 5. 自适应布局

布局依据可用窗口宽度而不是设备型号判断。下列宽度仅作为设计讨论基线，最终可随原型调整。

| 窗口形态 | 建议范围 | 主要布局 |
|---|---:|---|
| Compact | `< 600dp` | 单列对话；Work 列表使用抽屉；复杂操作使用底部工作面 |
| Medium | `600–839dp` | 对话保持主区域；列表、Tree 和详情可使用较宽弹窗或临时双栏 |
| Expanded | `≥ 840dp` | 主对话继续使用完整宽度；Tree、目录浏览器和详情优先使用主从布局 |

### 5.1 Compact 手机

- 单一主内容列，顶部身份与控制区压缩。
- 隐藏顶栏头像和 Git branch，完整信息仍可从 Project Status 查看。
- Model 在顶栏至少显示 provider；完整 `provider/model` 在选择面板中显示。
- 极窄屏允许顶栏分成两行：第一行是 Work / Session 与导航，第二行是 Model、Thinking、Context 和 Cost。
- 没有独立底栏。Resume 与 Tree 是输入卡片按钮行中间段的默认快捷按钮，用户可以删除、改名或换成自己的；它们也始终能从 Command Center 进入。
- Dialog、Tree、命令中心和大型 Composer 使用接近全高的底部工作面。

### 5.2 Medium 平板与展开中的折叠屏

- 利用额外空间增加列表可视行数和内容留白，控件保持适合触控的尺寸。
- Work 抽屉可以加宽，但默认仍应让用户专注当前对话。
- Tree、Session 选择器和目录浏览器可使用横向空间展示列表与详情。
- 横屏软键盘出现时，Composer 与发送操作保持可见。

### 5.3 Expanded 平板、桌面模式与大折叠屏

当前 WebConsole 的宽屏基线仍以对话为完整主工作面：

```text
┌─────────────────────────────────────────────────────────┐
│ 身份 / Git / Model / Thinking / 完整 Metrics / Work 导航 │
├─────────────────────────────────────────────────────────┤
│                                                         │
│                    对话主区域                            │
│                                                         │
├─────────────────────────────────────────────────────────┤
│ Queue / Widgets / Composer / 完整状态与快捷操作           │
└─────────────────────────────────────────────────────────┘
  Work 导航按需从左侧覆盖打开
```

- 完整显示 Git branch、`provider/model`、输入 / 输出 / Context / Cost 等统计。
- Desktop 按钮行显示前 6 个快捷按钮，手机显示前 3 个；其余在 Command Center 的「快捷按钮」组里。
- 对话历史与实时回复使用同一份完整内容宽度和边距，不建立两套版心。
- Work 导航默认延续临时抽屉；是否在超宽设备上提供可选固定模式留到原型阶段确认。
- Dialog 保持最大宽度，不随窗口无限拉伸。
- Tree 和目录浏览器优先采用“左侧导航、右侧详情与操作”的双栏形态。

### 5.4 折叠屏与多窗口

- 不让正文、选项或主要按钮跨越实体铰链或遮挡区。
- 窗口跨过布局阈值时原地重排，不重新打开页面或丢失状态。
- 分屏和自由窗口下按照实际宽度回退到 Compact / Medium，而不是按照设备类别强制大屏布局。

## 6. 主界面结构

### 6.1 顶部身份与控制栏

从左到右包含：

1. 阿露头像（Compact 可隐藏）。
2. `Workspace / Work` 身份区。
3. Git branch（仅在空间充足时显示）。
4. Model 选择器。
5. Thinking 选择器。
6. Context、Cost 等关键统计；输入、输出 token 等次要统计只在宽屏显示。
7. Work 导航按钮。

身份区整体可点击，通过同一个 Project Status 入口查看 Git、资源和 Work 状态。

### 6.2 对话主区域

- Assistant 消息左对齐，宽屏显示阿露头像；Compact 隐藏重复头像以节省空间。
- 用户消息右对齐，最大宽度小于正文区，带弱化时间信息。
- Markdown 支持标题、列表、引用、表格、链接和行内代码。
- 代码块显示语言、复制按钮和横向滚动；复制成功提供短暂反馈。
- Thinking 默认折叠，以冰蓝弱强调。
- Tool call 显示工具名、状态以及可展开的参数与结果，以琥珀色区分。
- 运行记录、上下文摘要和分支摘要使用中性折叠卡，与 Assistant 回复明确区分；落在两轮之间时是独立行，落在一轮里时属于那轮的过程。
- 图片在消息中内联展示，点击进入全屏预览；预览支持缩放、平移、关闭和系统分享（是否允许保存待定）。
- 更早历史通过明确的“加载更早记录”入口获取；加载后保持当前阅读位置。

#### 按轮组织（2026-09-30 起，#335）

一轮 = agent 一次运行，从开始到结束。当前运行按 `run.started` → `run.settled` 精确切分，中途 steer 的用户消息落在轮内；历史记录没有运行边界，用户消息开启一轮，到下一条用户消息前结束，用时取记录时间戳之差（近似；steer 过的历史轮会被切成两轮）。

- 每轮回复上方一行摘要：用时、工具调用次数（含失败次数）、状态（运行中 / 完成 / 已中止 / 失败 / 未完成）。失败的轮在摘要行直接显示错误。
- 点摘要行展开这一轮的过程（thinking、tool call、中间回复、提示），再点收起。收起时仍显示用户消息、图片、警告 / 错误和最终回复。展开 / 收起不改变阅读位置。
- 运行中的轮自动展开并实时计时，结束后自动收起；读者已离开底部时不在他阅读时收起。
- 发送后立即出现运行中的摘要行，它就是以前的「处理中」占位。
- 没有全局「详细 / 简洁」开关；桌面和手机同一套规则。

#### 流式回复与滚动

- 发送后先出现运行中的轮摘要行，与 Assistant 内容列对齐。
- 首段实际内容在摘要行下方出现，不另起无头像面板。
- 用户停留在底部时自动跟随；用户主动向上阅读后停止自动滚动。
- Android 端建议在停止跟随后显示“回到最新”悬浮按钮，并可附未读更新数量。
- 用户主动发送新消息时恢复跟随最新位置。

#### 详细 / 简洁模式（已删除）

2026-09-30 前用一个全局开关按类型藏块；它已被上面的按轮组织替代（#335）。本节仅作追溯。

### 6.3 Composer

Composer 固定在对话下方，由以下区域组成：

1. Extension 状态行（如有）。
2. Queue 摘要。
3. Extension Widget（如有）。
4. 已选附件预览。
5. 输入卡片：上面是整行宽的多行文本输入，内容超过两行时右上角出现展开编辑按钮；下面是一行按钮。
6. 按钮行从左到右：附件、工作区 │ 快捷按钮 │ 命令中心、发送。两端固定键手机只显示图标，桌面带文字标签和 `Ctrl+K` 提示。中间的快捷按钮由用户配置（默认「恢复」= `/resume`、「Tree」= `/tree`），手机和桌面都显示用户起的名字；名字约 4 个汉字 / 8 个字母，放不下时长名字先截断，短名字保持完整。

交互要求：

- 触屏软键盘中的发送动作与可见发送按钮语义一致；多行输入仍需容易实现。
- 外接键盘可保留 `Enter` 发送、`Shift+Enter` 换行；不得让手机用户依赖这一规则。
- 输入随内容增高，到达上限后内部滚动。
- 快捷 Composer 与大型 Composer 共用同一份草稿和附件状态。
- 大型 Composer 中，返回、关闭或系统返回只收起并保留草稿；发送只能通过明确按钮触发，避免误发长文本。
- 操作提交期间禁用重复发送，但不清除用户在请求期间继续输入的新内容。

### 6.4 输入卡片内的辅助操作

现有 WebConsole 的主要入口包括图片、图库、刷新状态、详细/简洁、Command Center 和中止；官方客户端已去掉详细/简洁按钮（见 6.2 按轮组织），其余入口都在输入卡片的按钮行里，没有单独的底栏。

- 按钮行在手机 360dp 宽下一行放下附件、工作区、三个快捷按钮、命令、发送，不换行、不横向滚动。
- 快捷按钮 = 名称 + 文本 + 方式。「立即发送」等于手打这段文本再发送，但输入框里的草稿、附件和取回的图片原样保留；「填入输入框」把文本放到草稿前面、光标在末尾，不发送。不检查当前 Work 有没有这条命令。编辑在 Command Center：命令旁的图钉打开预填好的表单（可以接着写参数），「管理快捷按钮」里新建、修改、排序、删除。配置只存在本机，所有 Host 共用。
- 连接状态灯在顶栏标题前，点开是说明和恢复动作；它与 Agent 运行状态（中止胶囊）是两个不同指示器。
- 没有独立的刷新按钮。“刷新状态”在 Command Center 里，也是连接状态弹层的默认动作；Web 的“刷新网页”不照搬。
- “中止当前回复”只在运行中可见：悬浮于输入区上沿右侧，带本轮计时，同时就是 Agent 运行指示器；不运行时界面上没有中止控件。它不得与“停止整个 Work”使用相同位置和样式。

### 6.5 Work 导航

Work 列表按以下分组：

- **当前工作**：正在运行或停止中的 Work。
- **可以继续**：可重新打开的 Work。
- **历史工作**：已经结束且不能继续的记录。

每一行显示：状态点、名称、目录摘要和状态文案。当前选中项使用粉色弱背景与边框。

操作方式：

- 点击行打开对应 Work。
- “继续”作为行内明确动作或详情动作。
- “移除历史记录”放入溢出菜单或详情区，并要求确认。
- 顶栏提供刷新，列表首部提供醒目的“新建工作”。
- 手机使用遮罩抽屉；点击遮罩、系统返回或选择 Work 后关闭。
- 大屏默认仍可使用临时抽屉，保持对话主区域完整；如以后增加固定模式，必须允许收起。

## 7. 主要流程

### 7.0 首次连接、配对与 Host 管理

本节以 Sunshine + Moonlight 的成熟心智模型为主要参考：**一次配对识别一台 Host，同一 Host 下保存多个可变化的网络地址，客户端根据当前网络自动尝试可用路线**。AluDock 不照搬其协议或界面，但必须达到“在家优先走局域网、出门自动回退到已设置的广域网域名，用户不需要重新配对或手动切模式”的体验。

首次配对是应用的正常产品流程，用户应能通过界面引导独立完成。流程不要求设置环境变量、编辑配置文件、理解证书或手动复制指纹。

#### 首次打开

没有已保存的 Host 时，首页只提供清楚的两条路径：

1. **连接新的 AluDock**：进入引导式配对。
2. **了解如何在电脑上打开配对**：用三步图文说明在 Host 本机启动 AluDock、打开五分钟配对窗口、保持手机可访问该电脑。

配对向导使用以下用户流程：

```text
输入电脑地址与端口
  → 检查能否到达 AluDock
  → 在电脑端打开配对窗口
  → 手机显示四位配对码
  → 用户把配对码输入电脑端
  → 验证并保存这个 Host
  → 进入 Work 列表
```

- “地址”与“端口”分开输入。地址支持局域网 IP、IPv6 或域名，并提供格式示例；不要求用户拼接 URL。
- 端口可预填产品约定的默认值，并允许修改；提示用户从 Host 界面确认实际端口。
- 检查失败时区分“地址格式不对”“连接不到电脑”“端口上不是 AluDock”“配对窗口未打开”和“验证失败”，并给出对应的下一步，而不是统一显示网络错误。
- 四位配对码由客户端生成并只显示给用户；界面明确提示“请在电脑上的 AluDock 中输入”，不能反过来要求用户把 Host 上的码填到手机。
- 配对轮询显示“等待你在电脑上确认”、剩余时间和取消入口。应用切到后台或网络短暂变化时保留本次进度。
- 只有完成 Host 身份验证、保存凭据，并重新连接成功后才能显示“配对完成”。最终结果暂时无法确认时显示“正在确认”，不能另起一次新配对。

#### Host 是一级用户对象

客户端为每台已配对的 AluDock 保存独立 **Host 档案**，分别管理身份与连接地址。每份档案至少包含：

- 用户可修改的显示名称，例如“家里的工作站”。
- 已验证的局域网和广域网连接地址。
- 当前首选地址、最近成功连接时间和连接状态。
- 可在高级信息中查看的 Dock 版本和身份摘要；证书指纹不作为普通列表标题。

多台 Host 不能因为名称、IP、端口或 Work 目录相似而自动合并。切换 Host 后，Work 列表、上次选中 Work 和草稿上下文分别保存，避免把一台电脑的状态显示到另一台电脑下。

#### 配对后添加广域网地址

局域网配对完成后，用户从该 Host 的“连接地址”页面添加外网域名 / IP 和映射端口，而不是重新配对：

```text
Host 设置
  → 连接地址
  → 添加广域网地址
  → 输入域名或 IP、端口和可选备注
  → 验证“这是同一台 AluDock”
  → 保存并可设为首选
```

- 地址只负责找到 Host，不决定 Host 身份。客户端必须继续使用首次配对保存的 Host 身份进行验证。
- 新地址只有在双向认证、精确 Host 证书校验和正常协议握手都成功后，才能标为“已验证”并参与自动连接。验证不匹配时明确显示“这个地址不是当前配对的 AluDock”，且绝不覆盖原 Host 凭据。
- 无法立即从当前网络访问的地址可以保存为“待验证草稿”，但不能自动使用，也不能显示为已配置成功。
- 同一 Host 可以有多个地址，例如“家中局域网”和“外网域名”。默认采用自动路线：优先最近成功地址与已验证局域网地址，局域网不可达时自动尝试已验证广域网 / VPN / 手动地址；回到家后重新探测并恢复低延迟局域网。普通用户无需维护“当前在家 / 外出”开关。
- 自动连接只能在同一 Host 档案内尝试这些已验证地址，不能跨 Host 猜测或合并。Host 详情显示本次实际通过“局域网 / 广域网 / VPN / 手动地址”中的哪条路线连接，便于排障，但不要求用户每次选择。
- 切换 LAN 地址、DDNS 域名或 NAT 映射端口不要求重新配对；Host 证书确实变化时则停止连接并要求用户重新配对，不能提供“忽略证书错误”。
- 广域网配置页面应提示用户：端口映射、防火墙、VPN / 隧道由其网络环境决定；客户端负责验证目标身份，但不会自动修改路由器。

#### Host 与配对管理

设置中提供“Host 与连接”一级入口，包含 Host 列表和每台 Host 的详情。普通用户可以完成：

- 新增并配对另一台 Host。
- 修改 Host 显示名称。
- 添加、验证、排序、停用或删除连接地址。
- 手动测试某个地址，并查看最近一次失败的通俗原因。
- 选择“自动选择已验证地址”或固定首选地址；自动切换时只做无副作用的读取重连，不重放结果未知的修改操作。
- 从本设备删除某个配对。

“删除本机配对”只移除当前客户端保存的凭据；“在 Host 上撤销此设备权限”需在 Host 本机管理界面完成。两项操作分别说明影响，删除前要求用户确认。

敏感凭据、完整证书和私钥永远不进入 WebView、日志、复制板或普通导出。备份 / 迁移配对信息若以后提供，必须另行设计加密和用户确认，不能把内部文件暴露成“高级设置”。

### 7.1 启动与当前 Work

启动后可以恢复上次使用的 Work，也可以先进入 Work 列表；具体默认入口留到原型阶段确认。没有可恢复对象时进入 Work 列表或空状态，任何方案都不得自动假定某个默认工作目录。

状态表现：

- **读取中**：保留应用壳，显示“正在读取当前工作”。
- **可用**：展示对话并建立实时更新。
- **连接已中断**：展示同一个 Work 的状态卡和“继续这个 Work”。
- **运行故障**：展示错误摘要和“重新启动这个 Work”。
- **正在停止**：禁用无效操作，允许刷新状态。
- **已停止**：作为历史 Work 展示，不显示 Composer。
- **没有 Work**：展示新建和恢复入口。

状态卡应显示 Work 名称、目录、状态和可执行动作。内部 ID 只放在可复制的详情区，不作为主标题。

### 7.2 新建工作：目录浏览优先

Android 端**不继承** WebConsole 当前的固定 workspace 列表或“默认工作目录”设置。新版 AluDock 提供目录浏览能力后，New Work 的标准流程为：

```text
新建工作
  → 浏览目录
  → 进入目标目录
  → 确认“使用此目录”
  → 创建并进入 Work
```

目录浏览器使用可点击、可触摸的图形界面，用户可直接浏览并选择目录：

- 顶部显示当前路径，并提供返回上级。
- 路径较长时使用可横向滚动或逐级展开的 breadcrumb，保留最后一级的完整名称。
- 主区域按行展示目录名、图标及可用的辅助信息。
- 点击目录行进入该目录；底部主按钮选择“当前目录”，避免“点击是进入还是选择”的歧义。
- 显示加载、空目录、无权限、目录失效和重试状态。
- Compact 使用全屏浏览器；Expanded 可使用目录树与当前目录内容双栏布局。
- 可复制或手动查看完整路径，但不把手输路径作为唯一方式。
- 是否记住最近位置、显示收藏或最近目录属于待定项；无论如何都不能重新形成一个强制默认目录。

“恢复保存的 Pi Session”可作为 New Work 内的独立次级入口，不与普通选目录混在同一列表中。

### 7.3 新建、恢复和管理 Session

- **New Session**：在当前 Work 内开始全新上下文，Work 和目录不变。此操作放在 Command Center，避免误触。
- **Resume Session**：使用可搜索列表，显示名称、目录、最近更新时间和短身份信息。
- 列表首次打开从顶部开始，不依赖键盘移动。
- 恢复、切换或替换 Session 时显示明确进度；取消后保留当前 Session。
- Rename、Compact 和 Reload 属于低频管理操作，统一放入 Command Center。

### 7.4 Session Tree

Tree 在 Android 上采用触控优先的图形界面，节点浏览与动作选择都提供可视入口。

#### 信息展示

每个节点建议包含：

- 展开 / 收起箭头。
- 节点类型图标（用户、Agent、工具、摘要等）。
- 摘要或标签。
- 时间和必要的辅助身份。
- 当前节点标记、状态 Badge 和父子连线。

当前分支首次打开时自动展开，并提供始终可发现的“定位当前节点”。用户开始浏览其他位置后，不应因后台更新反复把滚动位置拉回当前节点。

#### 触控交互

- 点击展开箭头：只展开或收起，不切换 Session。
- 点击节点正文：选中节点并展示详情，不立即执行分支操作。
- Compact：节点详情与动作进入底部面板。
- Medium / Expanded：左侧 Tree、右侧节点详情和固定动作区。
- 长按可打开快捷菜单，但所有动作也必须出现在详情区。
- 搜索、筛选、滚动和展开互不覆盖用户当前选择。

#### 搜索与筛选

保留并图形化现有分类：

- 全部
- 对话
- 用户
- Agent
- 无工具
- 已标记

筛选使用可横向滚动的 Chip，并显示数量。搜索应覆盖完整已加载节点；命中项要展示必要的祖先路径，避免搜索结果失去树上下文。筛选与搜索只改变视图，不修改 Session Tree 本身。

#### 节点动作

选中节点后，根据节点能力显示：

- **直接切换**：切换到该节点。
- **摘要后切换**：先保留被放弃分支的摘要，再切换。
- **Fork**：从用户消息位置分叉，并把可继续编辑的内容带回 Composer。
- **Clone**：从该节点创建新的 Session。

不可用动作保持可见、置灰并说明原因。只有可能影响正在执行的回复、未发送草稿或用户当前上下文时，才增加确认步骤。

#### 键鼠增强

- 方向键移动焦点，左右键展开 / 收起，Enter 选中。
- 鼠标悬停显示行反馈，右键打开与长按一致的菜单。
- 滚轮和触控板自然滚动。
- 上述能力均不得替代触控入口。

### 7.5 Queue、取回与中止

- Queue 位于 Composer 上方，以单行摘要显示数量和消息预览。
- 点击 Queue 可进入列表查看每条待处理消息；“取回”将尚未执行的文字和附件追加回当前草稿，不覆盖用户新输入。
- 取回不完整时明确指出哪些内容无法恢复，不能显示“已全部取回”。
- 中止当前回复时，Host 一步停下回复并取回所有尚未执行的排队消息，放回草稿的方式与“取回”相同；已经交给 Agent 的消息说明无法取回，但不阻止中止。
- “中止当前回复”和“停止整个 Work”必须保持明显区分：前者是运行控制，只在运行中以悬浮胶囊出现在输入区上方；后者是低频生命周期操作，只在命令面板中并需要确认。

### 7.6 Command Center

Command Center 为低频功能和扩展命令提供统一图形入口，用户通过搜索和选择找到命令。

目录页：

- 顶部搜索框。
- 按 WebConsole、Extension、Skill、Prompt 等来源分组。
- 每项包含图标、名称、说明和来源 Badge。
- 点击即可选择；物理键盘可使用上下键与 Enter。

命令运行页：

- 显示命令名称、来源与说明。
- 提供自由参数输入和明确的“运行”按钮。
- 本次命令的临时状态与输出显示在 Command Center，与主对话内容分开。
- 如果命令启动 Agent，后续正式内容回到主对话。
- 关闭面板不等于取消已经提交的命令。

Compact 使用接近全高的底部工作面；宽屏使用居中的宽 Dialog 或右侧工作面。`Ctrl/Cmd + K` 可保留给外接键盘，但界面中始终保留命令按钮。

### 7.7 Model、Thinking、Tools 与 Settings

- Model 与 Thinking 是高频项，保留顶栏快捷选择器。
- Model 选择面板显示完整 `provider/model`，支持搜索并标记当前项。
- Compact 顶栏空间不足时可以只显示 provider，但面板内不得省略完整身份。
- Tools 使用可搜索列表并标记 ACTIVE；点击后切换状态，结果在原位置反馈。
- Settings 根据值类型提供开关、枚举、数字、文本或结构化编辑器；只读项明确标记。
- Tools 与 Settings 是否进入首版待定，但交互不应退化为要求用户输入命令。

### 7.8 Project Status

点击顶栏身份区打开统一的只读状态面，包含：

- Work 名称、目录、生命周期和运行状态。
- Git branch。
- Model、Thinking、Context、Cost、Queue 与最近运行。
- Active Tools。
- Extensions、Skills、Prompts、Project Context 和 Diagnostics。

Compact 下每行约两张指标卡；宽屏可使用三列或更多。加载失败只影响对应 section，不关闭整个面板。

### 7.9 Dialog 与 Extension UI

支持统一的：

- Select
- Confirm
- 单行 Input
- 多行 Editor
- 只读 Viewer

交互规则：

- Compact 使用底部工作面，Medium / Expanded 使用居中 Dialog 或双栏面板。
- 必须提供关闭或取消按钮，并支持系统返回。
- 点击普通 Dialog 的遮罩不直接取消，只给出轻微注意反馈，防止误触丢失输入。
- 只有轻量媒体选择器可以点击遮罩关闭。
- 提交后保持面板可见并锁定操作，直到结果明确；临时断线时保留待确认状态。
- Select 列表支持搜索、触摸选择、键盘焦点和空状态。
- 长列表仅渲染部分内容时，界面必须明确提供继续浏览，不让用户误以为列表完整。

Extension 的 status 和 widget 可显示在 Composer 上方或下方。长 Widget 使用可展开卡片：宽屏首次建议展开，Compact 首次建议收起；更新内容时尊重用户当前展开状态。

### 7.10 附件与媒体

通用客户端统一使用“附件”概念：原生文件选择器可以发送图片、文档及其他 Dock 支持的文件，不沿用 WebConsole 的“图片 / 图库”入口和 Studio 媒体运输。

- 使用系统文件选择器作为基础入口。
- 选中后在 Composer 上方显示附件卡片，可逐项移除。
- 支持多选、上传进度、失败重试和数量上限提示。
- 图片附件可按媒体类型提供内联预览，但仍属于附件，不创建客户端图库。
- 平板键鼠环境可额外支持拖放和剪贴板粘贴，但手机不依赖这些方式。

WebConsole 现有的 Studio 图库、浏览器上传链路和“插入本机视频路径”不属于通用客户端能力。

## 8. Android 导航与输入约定

### 8.1 系统返回

返回优先级建议为：

1. 关闭当前菜单或节点快捷菜单。
2. 收起最上层 Dialog / Bottom Sheet，并保留尚未提交的输入。
3. 关闭 Work 抽屉。
4. 返回上一个应用页面或交给系统。

返回不得自动取消正在运行的 Agent、已提交命令或仍待确认的操作。

### 8.2 软键盘

- 键盘弹出后输入框、附件和发送按钮仍可见。
- 大型 Composer 随可用高度缩放，而不是被键盘遮挡。
- Tree 搜索和 Command Center 搜索关闭键盘后仍保留查询。
- 切换到外接键盘后不改变已经输入的草稿。

### 8.3 触控目标与无障碍

- 主要点击目标建议不小于 `48dp`；紧凑图标按钮也应有足够的不可见触控区域。
- 所有图标按钮提供可读名称，状态点同时有文字语义。
- 支持 TalkBack 的合理阅读顺序、标题、列表层级与状态播报。
- 不仅依靠粉 / 蓝 / 红区分状态。
- 支持系统字体缩放、减少动画和高对比度需求。

## 9. 状态与反馈规范

| 场景 | 建议反馈 |
|---|---|
| 初始读取 | 保留应用壳，显示局部加载，不使用全屏空白 Spinner |
| 实时连接正常 | 绿色状态点；无需持续文字打扰 |
| 正在连接 / 恢复 | 琥珀状态点和简短状态文案 |
| 离线或连接失败 | 红色状态点、保留现有内容、提供刷新状态动作 |
| Agent 正在响应 | Assistant 内容列内的粉色活动指示 |
| 消息进入 Queue | Composer 上方出现 Queue 数量与摘要 |
| 操作提交中 | 对应按钮进入 pending，禁止重复提交 |
| 操作失败 | 在最相关的组件内显示错误，并提供重试或刷新 |
| 结果暂时无法确认 | 不显示成功；提示可刷新状态确认，其他操作照常可用 |
| Work 不活跃 | 使用完整状态卡替代失效 Composer |
| 空对话 | 阿露品牌图与简短就绪文案，不堆叠教程 |

短暂通知可以自动消失；错误、警告、Queue 和需要用户处理的状态不能只使用一闪而过的 Toast。

## 10. 功能取舍基线

此表记录早期调研中保留、调整和省略 WebConsole 功能的取舍方向。它不定义最终版本排期；表中的“必须”按第 1 节约束词解释，首版范围另行确认。

| 能力 | 当前方向 | 说明 |
|---|---|---|
| Work 列表、状态、继续与历史 | 必须 | Android 主导航基础 |
| New Work 目录浏览 | 必须 | 替代固定 workspace / 默认工作目录 |
| 对话、历史与流式更新 | 必须 | 主工作面 |
| Markdown、代码、thinking、tool | 必须 | 保留高级对话表现 |
| Composer、共享草稿、发送 | 必须 | 触控优先 |
| Queue、取回、中止当前回复 | 必须 | 关键运行控制 |
| New / Resume Session | 必须 | Session 基础管理 |
| Session Tree | 必须 | 重点做成图形化高级交互 |
| Model / Thinking | 必须 | 高频控制 |
| Command Center | 建议首版保留 | 替代命令记忆与纯键盘操作 |
| Extension Select / Confirm / Input / Editor | 建议首版保留 | 保证图形交互完整性 |
| Project Status | 建议保留 | 统一状态与诊断入口 |
| Tools / Settings | 待定优先级 | 保持 GUI 方案，不要求首版全部落地 |
| 详细 / 简洁模式 | 已删除 | 改为按轮展开 / 收起过程（#335） |
| 大型 Composer | 建议保留 | 适合长文本与平板 |
| 图片附件内联预览 | 建议保留 | 仍按附件处理，与普通工具结果同层展示 |
| 原生文件附件 | 必须 | 通过系统文件选择器发送 Dock 支持的文件 |
| Studio 图库 | 不继承 | 通用客户端不创建图库概念 |
| 本机视频路径插入 | 不继承 | 不向 Host 暴露客户端本机路径 |
| 固定 workspace 列表 | 不继承 | 改用目录浏览 |
| 默认工作目录设置 | 不继承 | 不再作为 New Work 前置配置 |
| 刷新网页 | 不继承 | 使用刷新状态 / 重新连接 |
| TUI 式键盘限定交互 | 不继承 | 键盘只作为增强输入 |

## 11. 术语与核心文案

为避免 Work、Session 与当前回复混淆，建议稳定使用以下术语：

| 概念 | 推荐文案 | 不建议 |
|---|---|---|
| Dock Work | Work / 工作 | 统一叫“会话”或“项目” |
| Pi Session | Session / 会话上下文 | 与 Work 混用 |
| Create Work | 新建工作 | 默认工作目录启动 |
| Reopen Work | 继续这个 Work | 新建同名 Work |
| Abort run | 中止当前回复 | 停止工作 |
| Stop instance | 停止整个 Work | 中止 |
| Pending messages | Queue / 排队消息 | 缓存 |
| Restore queue | 取回排队消息 | 撤销发送（可能不准确） |
| Session Tree | Session Tree / 会话树 | 终端树 |
| Refresh state | 刷新状态 | 刷新网页 |

危险操作文案必须明确对象，例如：

- `中止当前回复`
- `停止整个 Work`
- `从历史列表移除`
- `切换到此节点`

界面不展示 controller、lease、generation、cursor 等内部术语。面向用户只描述连接、Work、Session、运行和操作结果。

## 12. 后续原型验收原则

未来进入原型或开发阶段时，至少应满足：

1. 不接键盘，仅用触摸可以完成 New Work、发消息、恢复 Session、浏览 Tree、切换 Model 和中止回复。
2. Tree 的节点选择与节点动作分离，不会因普通点击立即切换上下文。
3. 手机竖屏、手机横屏、展开折叠屏和大平板均无被裁切的主要操作。
4. 窗口改变尺寸后，草稿、Tree 选中项和对话阅读位置不丢失。
5. 断线时保留已读内容和草稿，并明确显示恢复状态。
6. 用户离开对话底部后，流式输出不抢夺滚动位置。
7. “中止当前回复”和“停止整个 Work”不会被视觉或文案混淆。
8. 任何核心能力都不要求用户记住斜杠命令或快捷键。
9. TalkBack 能读出主要导航、消息角色、按钮名称和连接状态。
10. Android 端与 WebConsole 并排查看时，能明显识别为同一产品家族。
11. 新用户不借助命令行即可输入地址和端口、完成首次配对，并能看懂等待、超时和失败状态。
12. 给已配对 Host 添加广域网地址时，只有验证为同一个 Host 后才能启用；错误地址绝不覆盖已有配对。
13. 用户能区分“删除本机配对”和“在 Host 上撤销设备权限”，并知道撤销权限需在 Host 本机完成。

## 13. 待确认事项

在进入正式 UI 原型前，需要产品侧继续确认：

- Android 首版具体保留哪些 WebConsole 功能。
- Expanded 布局是否默认固定 Work 导航。
- Tree 右侧详情需要展示到什么深度，是否提供消息内容预览。
- Command Center 与 Extension UI 是否进入首版。
- Android 本地图片附件、Studio 图库和媒体预览的首版边界。
- 是否保留发送时间预览、详细 / 简洁偏好等本地展示设置。
- 是否需要中、英、日多语言，还是先维持当前中文主界面。
- 产品最终名称、应用图标与启动画面是否直接沿用“阿露终端”。
- Host 发现是否由 Dock 提供正式能力；在此之前以清楚的地址 / 端口录入为主，不伪造自动发现。
- 广域网连接推荐端口映射、VPN 还是其他网络方案；客户端无论采用哪种方式都必须验证为同一 Host。
- 是否提供配对凭据的跨设备迁移；在安全方案确认前不提供明文导入导出。

待确认事项保留为历史记录；本文继续按头部声明的优先级提供视觉与交互背景。
