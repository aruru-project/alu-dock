# V0.1 Night Console 视觉合同

日期：2026-07-16

卡片：#156

状态：V0.1实施基线；完整renderer与主题系统留给#148

## 1. 方向

Night Console是一套安静、密度可控的深色终端工作台，而不是Web聊天界面的终端复刻。

- 假定当前自用终端已经是深色背景；Dock不设置、清屏或接管整个终端背景。
- 使用single-column transcript，不使用左右气泡、avatar或常驻`You`/`Assistant`标签。
- 层级主要来自局部surface、rail、状态符号、间距和低饱和语义色，而不是重复标题。
- conversation、pending queue、composer和两行status dock形成唯一纵向工作流。
- V0.1不建设背景探测、浅色主题、theme picker或可配置token系统。现有`NO_COLOR`安全退化保留，但不是本卡扩展矩阵。

## 3. Transcript

### 用户消息

- 无`You`标签。
- `▎`rail后使用局部navy surface，surface只覆盖该消息的投影宽度，不影响屏幕其他区域。
- 多行和CJK按现有ANSI-safe wrapper处理；entry/row anchor包括surface行，不改变#155分页语义。

### Assistant

- 无`Assistant`标签，Markdown直接落在终端原生背景。
- streaming状态由history与pending/composer之间固定单行activity slot以Host事件驱动的稳定phase符号表达，不在每个message/footer上重复，也不运行独立spinner/paint timer。

### Thinking

- 无`Thinking`标题。
- 每行使用`│`rail、低饱和violet和italic；`hideThinking`仍完全移除该projection。

### Tool

- collapsed summary只有一行：`◆ name running`、`✓ name done`或`× name failed`，并以#161安全allowlist附加read路径/范围、bash首行、edit/write目标与计数，保留`Alt+O detail`。
- expanded以同色rail连接局部低饱和args/result surface；diff不加大面积背景，保留增删局部对比。
- #157 per-entry width/revision/expanded cache继续有效；视觉变更不加入定时paint或全history重排。

### Queue、notice和error

- pending queue保持在composer上方，`↳`明确表示尚未进入正式transcript。
- `message_start`消费、Alt+Up恢复、Esc恢复后abort等#154语义不因视觉层改变。
- 普通notice使用`·`，续行使用`│`；error使用`!`。历史paused使用queue色和`↑`，不伪装成消息。成功no-run `command.handled`只清理activity，不生成通用notice；rejection、extension error/notification和命令专用结果仍可见。

## 4. 固定布局

从上到下：

1. 一行产品header：`ALU DOCK / NIGHT CONSOLE · /help commands`；
2. app-owned history viewport；
3. 固定一行activity slot：ready/submitting/waiting/thinking/responding/tool/retry/compaction/queue/interaction/abort/error/disconnected只替换该行内容；
4. terminal selection hint（仅Alt+M/`/mouse`显式模式出现）及pending queue tray（仅有pending时出现）；
5. multiline composer；
6. 最多两行低频status dock。

完整快捷键只在`/help`中展示。Composer仍固定在viewport内；其底边紧邻两行status dock，不使用terminal-native scrollback作为conversation history。

Status第一行优先级：lifecycle/execution → queue → model → configured thinking → connection/controller → extension status。live activity不得回到footer。

Status第二行优先级：name → cwd → Dock/Pi短ID → tokens → context → cache → cost → compaction。

字段逐项按可用宽度加入，不把一个长字段切成不可读碎片：

- 120列通常展示完整model、connection、extension、identity和metrics；
- 80列保留独立activity slot、footer state/model以及identity和可容纳的最高优先级metrics；
- 43列至少保留独立activity slot、footer state与identity；
- 高度不足时沿用既有规则先移除header/低优先级chrome，不能裁掉composer。

## 5. 不变量与延期

本视觉层不得改变：

- Host/runtime/extension/dialog Promise ownership；
- Protocol V2、capability或DTO；
- #154 queue consumption/dequeue；
- #155 bounded pagination、entry/row anchor和默认app-owned wheel；#160只通过成对mouse-mode切换恢复终端原生框选；
- #157 render cache与结构化tool state；
- #163 activity slot固定一行、footer无live phase且phase变化不得移动locked history anchor；
- Stage 4–6 replacement、lease、tree和Host-loss合同。

延期到#148或真实需求出现后再做：全屏背景、浅色主题、运行时theme切换、完整16色设计矩阵、component animation系统、图片renderer和任意第三方custom component。
