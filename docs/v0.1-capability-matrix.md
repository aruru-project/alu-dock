## 1. 判定口径

V0.1 的目标不是复刻公开 Pi TUI，而是在当前开发机的 SSH headless shell 中，让 Alu Dock 成为日常默认 Pi 研发终端。

- **MUST**：V0.1 冻结前必须完成并通过真人验收。
- **SHOULD**：当前 SDK/扩展已有直接价值，若实现中未出现新的阻断应完成；若延期必须在 #142 留下明确理由。
- **WON'T**：V0.1 明确不做，不能作为阶段实现的隐式前置条件。
- **Host-only**：只能在持有 Pi SDK runtime 的 Host 中调用。
- **Client-only**：只影响当前 TUI，不写入 Pi 或 Dock 持久状态。

绑定不变量：

1. `systemd --user` 管理唯一常驻 Host；普通 `open/new/attach` 不再自行 fork detached Host。
2. Host 是 `AgentSessionRuntime`、extensions、tools 和运行 Promise 的唯一 owner。
3. Dock `instanceId` 与 Pi `sessionId/sessionFile` 分离。
4. Host loss 后只恢复 catalog 事实；旧命令、队列、Promise、tool side effect 永不自动续跑或重放。
5. 用户可以对 `host_lost|runtime_error` 记录执行**显式 reopen**，从已验证的Pi `sessionFile/recoverySessionFile`新建generation+1 runtime并恢复对话上下文；这不是恢复旧执行。
6. Managed catalog只保存身份/session metadata和保守intent/count；不保存prompt/tool payload、queue text、interaction、Promise或event log。Startup reconcile不构造runtime。
7. TUI 只消费结构化 DTO/event，不解析 ANSI 屏幕。
8. 只使用包根导出的 Pi 公共 API。唯一现存例外是 `PromptOptions.preflightResult`：它虽在公开类型中但标为 internal RPC hook；V0.1 若继续使用，必须封装在 Pi adapter 内并在 SDK 升级门禁重新审核。

### Replacement 失败语义

`AgentSessionRuntime` 会先 teardown 旧 session，再创建目标 runtime，因此 replacement 不是事务性 API。Dock 必须：

1. replacement 前持久化 intent：operation ID、kind、`previousSessionFile`、requested target/entry；所有 kind 的自动 recovery source 固定为 previous session file；
2. extension cancel 时清除 intent，尚未 teardown；成功时原子提交目标 durable session metadata、下一 runtime generation 并清除 intent，之后才发布 snapshot；Pi尚未物化candidate JSONL时不把不存在路径写成durable `sessionFile`，而临时保留previous durable file为live recovery；
3. Factory/bind 失败时 dispose candidate；若错误状态可 durable commit，则进入 `runtime_error/unavailable` 并写 `recoverySessionFile=previousSessionFile`。若目标 catalog commit 本身失败，则不能宣称已持久化 runtime_error：dispose candidate、保留旧 replacement intent、Host 进入 `mutation_faulted`，由下一 epoch 保守归一；
4. 允许用户显式 reopen recovery/其他已知 session file；不得把失败包装成“仍在旧会话”。

这属于已知实现风险，不是产品阻塞。

## 3. Settings 矩阵

所有可持久化设置沿用 Pi `SettingsManager`：实例启动读取内存快照；setter 更新当前 runtime 并异步落盘；写入通过 Pi 文件锁和 modified-field merge，同字段 last-writer-wins；其他实例不实时同步。

任何“保存成功”都必须经过：setter → `await settingsManager.flush()` → `drainErrors()`。Dock 不增加 CAS、冲突提示、版本向量或自动合并层。

| 设置组 | V0.1 | 说明 |
|---|---|---|
| default provider/model、thinking | MUST | 使用 session 公共 setter；显式操作允许更新 Pi 全局默认。 |
| auto compaction、auto retry | MUST | 读写 Pi setter；保留项目 `.pi/settings.json` 的 `reserveTokens=165536`、`keepRecentTokens=20000`。这两个无公共 setter，V0.1 只读展示。 |
| steering/follow-up mode | MUST | Pi session setter，影响 queue delivery。 |
| transport、HTTP idle timeout | MUST | Pi setter；网络 dispatcher 是 Host 进程级资源，proxy/dispatcher 变更标记为需要 Host restart，不伪装成 per-instance 隔离。 |
| skill commands | MUST | Pi setter；reload 后刷新 command catalog。 |
| hide thinking、cache miss notice | MUST | Pi setter；当前客户端立即更新显示，其他客户端/实例不自动同步。 |
| tree filter、double escape | MUST（配合阶段 6） | 使用 Pi setter；双 Escape 的 UI 动作仍由 Dock TUI 解释。 |
| editor padding、output pad、autocomplete max、hardware cursor、clear-on-shrink、terminal progress | MUST | Pi 持久设置；当前 TUI 重新配置/重绘。 |
| default project trust、warnings | MUST | 沿用 Pi 语义；project trust 决定仍写 `~/.pi/agent/trust.json`。 |
| quiet startup、collapse changelog、install telemetry | SHOULD | 不阻塞核心日常流程；若展示必须使用 Pi setter。 |
| image 显示、image width/resize/block | WON'T（UI） | V0.1 不做图片粘贴或 SSH image；不得因此阻止 `show_image` tool 返回本地路径。 |
| theme 像素级兼容、自定义 theme paths | WON'T | 可保留 Dock 固定可读主题；不承诺 Pi theme parity。 |
| packages/extensions/skills paths 的安装编辑 | WON'T | 使用 `pi install/config`；Dock 只读 resource 来源和 reload。 |

焦点、scroll、当前 overlay、某条 tool 是否展开等纯瞬时状态只存在于当前 TUI。

## 4. Extension UI 语义矩阵

| UI 方法 | V0.1 | 语义 |
|---|---|---|
| `select` | MUST | 单 controller lease，稳定 interaction ID，timeout/signal/detach 时返回 `undefined`。危险扩展必须自行把 undefined 当拒绝。 |

| 字符串 `setWidget` | SHOULD | Host broker只接受 bounded declarative text lines并发 closed event；Stage 4 必需门禁不承诺持久 widget layout。component/factory 不跨 socket并只给一次诊断。 |
| `setTitle`、`setEditorText` | SHOULD | 当前 Stage 4 adapter显式 unsupported/no-op并给一次诊断；未伪装成已实现，后续若加入也只能发给当前 controller。 |

| `ctx.ui.custom()` | WON'T | 返回 unsupported/default；使用该功能的具体流程必须由扩展 source-adapt。 |

一个 instance 同时只有一个交互 controller。Observer 和其他客户端仍可读事件、发普通消息；只有 lease holder 可以回答 interaction。Lease 绑定 attach/event socket，断开立即释放并取消该 lease 的 pending dialogs。V0.1 不实现抢占、转移或多 controller 仲裁。

## 8. 阶段 0 阻塞结论

**GO：没有新的产品阻塞，可进入阶段 1。**

已经识别但有确定处理方案的工程风险：

1. runtime replacement 非事务性：失败进入 `runtime_error`，只允许显式 reopen；
2. project trust：Host 在 create 前按 Pi trust store/default 预检；需要交互时返回结构化 `project_trust_required`，由 TUI 明确选择后重试；当前七扩展无 `project_trust` handler；
3. `rm-confirm` 的 undefined 放行：已由 versioned local package `pi-rm-confirm@0.1.0` 修复并通过 `pi install` 替换 loose source；
4. systemd user PATH 不含 NVM Node：生成 unit 时写绝对 `process.execPath` 与 CLI 路径；
5. Undici dispatcher 是进程级：proxy/bootstrap 变更按 Host-global/restart-required 展示；
6. `preflightResult` 是 pinned internal hook：封装并加入 SDK upgrade gate，不扩散到 Dock 协议。

若后续发现当前七扩展的**主要研发路径**只能依赖被排除的 `ctx.ui.custom()`，或公开 Pi API 无法显式打开现有 session file，才构成 STOP/ADJUST 门禁。阶段 0 已通过源码确认 `SessionManager.open()` 与 `createAgentSessionRuntime()` 可支持显式 reopen。
