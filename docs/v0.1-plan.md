## 1. 最终产品边界

V0.1 是当前开发机上一次有终点的日常终端能力完整化：

- SSH headless、单机、单 Unix 用户；
- `systemd --user` 常驻唯一 Host；
- CLI/TUI 可 detach/reconnect，但不持有 SDK；
- 当前本机七个 extensions/packages 的主要研发路径是兼容基线；
- 完成 capability matrix 与真人默认入口门禁后冻结功能面。

Comment #228 是对旧边界的最新覆盖：systemd user Host 已是 MUST，不再是“生产部署非目标”。这不改变故障语义：Host loss 会终止当前 run；systemd 可启动新 Host，但新 Host不得自动继续、重试或重放旧 prompt/tool/queue。用户只能显式 reopen 原 Pi session context，并开始新的操作。

图片不构成 Dock 子系统：`show_image` 正常返回本地 path，SSH TUI 显示 path/普通结果；既有 Web/RPC 侧自行过滤 JSONL base64 并按 path 读取。Dock 不提供 image paste、inline render、artifact endpoint 或 binary transport。

## 2. 目标架构

```text
SSH terminal client(s)
  ├─ Editor / Markdown / generic tool UI / selectors / Footer
  ├─ one attach stream may hold interaction lease
  └─ protocol V2 over private Unix socket
                 │
                 ▼
systemd --user: alu-dock.service
  └─ DockHost (hostEpoch, readiness, admission)
      ├─ DockRegistry + private atomic catalog
      ├─ ManagedInstance (stable Dock ID/state/event ring)
      │   └─ PiRuntimeHost (mutable AgentSessionRuntime owner)
      │       ├─ AgentSession + SessionManager JSONL
      │       ├─ SettingsManager / ModelRegistry / ResourceLoader
      │       └─ DockExtensionUIContext
      └─ V2 projections: history/tree/resources/tools/settings/metrics/interactions
```

### Ownership

- `DockHost`：process epoch、socket、service readiness、全局 admission/drain。
- `DockRegistry`：live instance 与 catalog-only record 的唯一集合视图，串行 catalog mutation。
- `ManagedInstance`：Dock identity、lifecycle/execution/lastRun、event cursor、command/stop/replacement gate。
- `PiRuntimeHost`：当前可替换的 `AgentSessionRuntime`、rebind、dispose、Pi DTO projection。
- `DockExtensionUIContext`：基础声明式 UI broker；不把 Pi Component 发给 client。
- TUI：仅 terminal presentation、临时 editor/scroll/overlay 状态。

## 3. 阶段 0 已冻结的工程决策

### 3.1 systemd unit 分发

采用 **repository-owned generator + explicit service commands**：

- `alu-dock service install` 生成 `~/.config/systemd/user/alu-dock.service`；
- unit 的 `ExecStart` 写入安装当时的绝对 `process.execPath` 与绝对 `dist/src/cli.js`，避免当前 user manager PATH 不含 NVM Node；
- `service install --now` 执行 daemon-reload、enable、start，并用 V2 hello 等待真正 ready；
- `service start/restart` 同样等待 hello；restart 必须看到新 `hostEpoch`，并校验 hello PID 等于 unit `MainPID`；timeout 只报 unit/journal 诊断，不删除 catalog或循环重启；
- `service uninstall` 默认只 disable/remove unit，不删除 catalog/session；
- checkout 或 Node path 变化后重新 build/install unit。

普通 `alu-dock open/new/attach` **不自动调用 systemctl start，也不 fork detached child**。Host 不可用时快速返回 `service_unavailable` 和明确的 `systemctl --user status/start` / journal 指引。显式 `alu-dock service start|stop|restart|status|logs` 才管理 unit。

### 3.2 Readiness

采用 `Type=exec`（或实现时等价的 `simple`），不增加 sd_notify dependency。Systemd ActiveState 只表示 Node 已 exec；应用 ready 以 V2 hello 为权威。CLI/service installer 在 bounded timeout 内重试 hello。

Host startup 顺序：

1. 取得并做语法验证的 systemd runtime/state paths；
2. probe并绑定默认socket，先取得单Host ownership，但state仍是starting；
3. chmod并验证socket mode/identity；
4. 创建/验证private state directory，load/validate/reconcile catalog；
5. state → ready，hello开始成功。

Starting 期间连接只返回 `host_starting`，不执行 side effect。Catalog 失败时关闭自己 listener、inode-safe unlink，并非零退出。

### 3.3 Unit 语义

目标 unit 语义：

```ini
[Unit]
Description=Alu Dock per-user Host
StartLimitIntervalSec=30
StartLimitBurst=5

[Service]
Type=exec
ExecStart=<absolute-node> <absolute-cli> serve --managed
Restart=on-failure
RestartSec=2
TimeoutStartSec=15
TimeoutStopSec=15
KillSignal=SIGTERM
KillMode=mixed
UMask=0077
RuntimeDirectory=alu-dock
RuntimeDirectoryMode=0700
StateDirectory=alu-dock
StateDirectoryMode=0700
WorkingDirectory=%h

[Install]
WantedBy=default.target
```

不添加会破坏研发工具的 `NoNewPrivileges`、filesystem sandbox 或 PrivateTmp。Managed path 使用 journal，不写 runtime-dir `host.log`。

安装/status 检查 linger 但不自行修改机器 policy。本机已确认 systemd `255`、`Linger=yes`、`/run/user/1000` mode `0700`；user manager 的 degraded 来自无关 desktop portal/snap failed units，不是 Dock 阻塞，测试只断言 Alu Dock unit 自身状态。

### 3.4 Catalog

路径：`$STATE_DIRECTORY/catalog.json`；非 systemd test/dev fallback 为 `${XDG_STATE_HOME:-$HOME/.local/state}/alu-dock/catalog.json`。Socket 仍位于 `$RUNTIME_DIRECTORY/dock.sock`。

Catalog 初始 schema：

```json
{
  "schemaVersion": 1,
  "revision": 12,
  "lastHostEpoch": "uuid",
  "instances": [{
    "id": "dock-uuid",
    "creationOperationId": "operation-uuid",
    "name": "optional",
    "cwd": "/absolute/path",
    "createdAt": "...",
    "updatedAt": "...",
    "runtimeGeneration": 2,
    "lifecycle": "host_lost",
    "execution": "unavailable",
    "lastRun": "interrupted",
    "piSessionId": "...",
    "sessionFile": "/absolute/session.jsonl",
    "admissionPending": false,
    "pendingCount": 0,
    "lastKnown": {"lifecycle":"active","execution":"running","activeCommandId":"operation-uuid","pendingCount":1},
    "recoverySessionFile": "/absolute/session.jsonl",
    "interruption": {"reason":"host_crash","at":"..."}
  }]
}
```

只持久化身份、session path、最后事实、operation ID/count/intent 与 reopen metadata；不持久化 prompt、token delta、tool payload、queue **内容**、interaction 内容或 active Promise。`activeCommandId`、`pendingCount`、replacement/stop/shutdown intent 是 crash 后保守判定所需的最小事实。

写入：0700 state dir、0600 regular file、拒绝 symlink/wrong owner；same-directory temp → fsync file → atomic rename → fsync directory；Host 内单写队列。Corrupt/future schema 保存原证据并 fail startup，不自动清空。V0.1 不做自动 retention；记录量真实阻塞时另开卡，避免先建清理平台。

Managed mode 固定使用 systemd 提供的默认 runtime/state directory，拒绝 `--socket`/`--state-dir` override；它先取得默认 socket ownership 再加载 catalog，因此只有一个 writer。Custom socket 只属于 `serve --dev`/tests，并强制 in-memory 或调用方注入的独立 temporary store，绝不能指向 managed catalog。

各 mutation 的 pre-intent、candidate disposal、response-after-commit 与 startup normalization 顺序以 [`control-protocol-v2.md`](control-protocol-v2.md) 第 9–10 节为规范，不在实现中另创语义。

### 3.5 1.0 前绿地开发规则

Alu Dock 是全新项目。到 1.0 落地前，除非用户特意说明，不建设旧协议、旧 Host、旧 catalog 或旧 CLI 行为的兼容、迁移、双栈、upgrade path 或历史状态处理；原型实现可以直接替换。wire major `2` 是当前初始合同，不表示存在需要支持的已发布 V1。非 V2 hello/request 只按当前协议的非法输入统一拒绝，不增加版本专用分支或运维提示。capability 名称中的 `.v1` 仅表示该 capability 自身的首版 schema。

### 3.6 Project trust

当前 SDK construction 默认 `SettingsManager.create(... projectTrusted=true)`，与普通 Pi CLI trust bootstrap 不等价。V0.1 Host 必须在加载 project resources 前使用公开 `hasTrustRequiringProjectResources`、`ProjectTrustStore`、global `defaultProjectTrust` 做预检。

需要 ask 时先返回绑定 operation/target/canonical cwd 的 `project_trust_required` challenge，TUI 明确选择后重试 create/reopen/switch。该 gate 必须发生在 candidate construction、extension before-switch hook、replacement intent、teardown 和任何 mutation 之前；因此 switch 虽已有旧 runtime，第一次 challenge 仍没有触发 replacement side effect。当前七扩展未注册 `project_trust` handler；未知 handler 不进入兼容承诺。

### 3.7 Host shutdown 与 instance stop

- `instance.stop`：真正结束该 Dock instance，catalog → stopped，不可 reopen。
- Host graceful shutdown/restart：不能复用“显式 instance stop”的产品状态；应有 host-shutdown disposal path，把仍需保留的 instance 写为 `host_lost`/reopenable。
- 若 running abort 已经通过公开事件确认，可记 `lastRun=aborted`；crash/SIGKILL 只能记 `interrupted`，不得猜 tool side effect 结果。
- Host drain 总预算 12 秒，给 unit `TimeoutStopSec=15` 留出 kill margin；超时非零退出，下一 epoch 根据 durable shutdown/busy intent 保守归一。

### Dogfood UX 收敛：#147

阶段 3.6 真人使用发现 append-oriented布局、静态状态行和不可检索 selector不足以作为默认终端。阶段 4 前先完成一个 client-only切片：

- model及通用 DTO selector支持输入检索，focus/IME/resize由薄 `pi-tui` adapter处理。

该切片不增加 capability、wire字段、lease或 runtime ownership。它先冻结 Stage 4可复用的 overlay/focus/search/layout primitives；若实现必须 patch `pi-tui`、使用私有 API或无法保持 composer/focus，则停止并提前启动 #148，而不是继续堆 wrapper。当前公开 API审计未触发该条件。

Gate：纯 reducer/render specs、真实 PTY resize/scroll-lock/model search/tool toggle/detach，以及真实 Pi活动阶段 smoke。

## 6. 风险与已确定处理

| 风险 | 处理 |
|---|---|
| Host crash 后 side effect 结果未知 | `interrupted/host_lost`；不自动 retry/replay；response loss 视为 ambiguous。 |
| Runtime replacement 先 teardown 后 create | teardown 前 fsync replacement intent；recovery 固定 previous session。Factory/bind 失败且错误状态可 commit 时写 `runtime_error`；目标 catalog commit 失败时 dispose candidate、保留旧 intent、进入 `mutation_faulted`，由下一 epoch归一。绝不继续 stale session。 |
| systemd PATH 不含 NVM Node | unit generator 写绝对 Node/CLI 路径。 |
| user manager degraded | 只检查 Dock unit；本机无关 desktop failed unit 不阻塞。 |
| Linger/boot policy | install/status 检测并提示，不自动改 machine policy；本机 Linger=yes。 |
| Catalog 与 socket 双 Host | default socket 先取得 ownership再读 catalog；custom socket 必须独立 state dir。 |
| Process-global Undici/proxy | Host-global/restart-required；不伪装 per-instance 网络隔离。 |
| Settings 并发 | Pi 原生 field merge；同字段 last writer wins；flush/error 后回执。 |
| Project trust | runtime create 前结构化 preflight；saved trust/default semantics；当前扩展无 handler。 |
| Extension arbitrary component | 只做 typed broker；current extension source/fallback；custom 明确不支持。 |
| rm-confirm undefined 放行 | 建 versioned `pi-rm-confirm` local package、`pi install` 替换 loose source、detach/timeout regression；不 patch npm/cache。 |
| Pi internal preflight hook | 单 adapter 封装、pin 0.80.6、升级复核。 |
| Event ring 不持久 | Pi session history重建；cursor 含 hostEpoch；不建 event store。 |

## 7. 阶段 0 GO 门禁结论

当前没有需要用户再次拍板的重大语义，也没有外部工程阻塞：

- Pi 0.80.6 公开 `AgentSessionRuntime`、`SessionManager.open`、settings/resources/tools/stats/session APIs 足够；
- 当前七扩展的主要路径可由基础 UI broker覆盖，复杂 widgets/custom 可忽略或 source-adapt；
- 本机 systemd user manager、RuntimeDirectory/StateDirectory、linger 均可用；
- NVM PATH、degraded manager、project trust、replacement failure、rm-confirm fail-open 都已有确定工程处理；
- Web/image 不需要 Dock 新能力。

因此阶段 0 结论为 **GO**。下一入口是阶段 1 Runtime/协议底座；若实现中出现下列任一情况才停止并回到 #142：

1. 公开 Pi API 无法打开已知 session file 或完成 replacement-safe rebind；
2. 当前七扩展的主要研发路径必须依赖已排除的 arbitrary `ctx.ui.custom()`；
3. 单 Host/catalog ownership 在 systemd + socket 约束下仍无法保证；
4. 任何方案需要自动重放旧 prompt/tool side effect；
5. 必须修改 Pi 本体或旧 daemon/Rails/Redis/Alubot 才能继续。
