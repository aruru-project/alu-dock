# V0.2 Terminal Core 迁移设计

Date: 2026-07-15
Card: #148
Status: V0.1 后期设计冻结；V0.2 实施，当前不得提前切换 renderer

## 1. 决策

Alu Dock 在 V0.2 一次性移除对 `@earendil-works/pi-tui` 的直接依赖，改由本仓库维护面向 Dock 产品合同的轻量 Terminal Core。

这不是 Runtime 改造。`@earendil-works/pi-coding-agent` 继续只在 Host 侧提供 Pi runtime；Host、V2 wire、closed DTO、controller lease、catalog 和 extension Promise ownership 均不因 renderer 切换改变。Terminal Core 只处理终端输入、布局、渲染、focus、overlay、editor 和文本组件。

迁移不提供长期双 renderer、compatibility facade、旧 CLI alias 或 stock Pi `InteractiveMode` fork。新 Core 通过完整门禁后直接替换当前 V0.1 toolkit，随后删除依赖、imports 和临时 adapter。

## 2. 不可改变的边界

1. Host 仍是 runtime、extensions、tools、admission、状态、dialog Promise 和 controller lease 的唯一 owner。
2. TUI 继续只消费 closed snapshot/event/interaction DTO；Terminal Core 不得 import `src/pi/*`、`AgentSession` 或 control protocol parser。
3. renderer 不得改变 wire major `2`、capabilities、event identity 或 mutation semantics。
4. binary、image、data URI 和 raw base64 不进入 Core；图片仍只表现为安全本地 path 或 omission。
5. terminal-facing text 在领域投影和 renderer 边界继续过滤 C0/C1；仅 Core 自己生成受控 ANSI。
6. V0.1 已冻结的 viewport、search、activity、tool-fold、key action 和 extension dialog行为是迁移规格，不以 `pi-tui` 的现有行为作为新产品合同。
7. clean build、immutable release、active-instance restart refusal 和完整 rollback纪律保持不变。

## 3. V0.1 直接依赖盘点

冻结点为 Alu Dock commit `945c098dec3dbedc4010fcc9ea7a0b341d0f3d4a`，直接依赖 `@earendil-works/pi-tui@0.80.6`。

迁移前已经属于 Dock、必须直接保留语义的模块包括：

- `screen-layout.ts`：fixed composer、history viewport、scroll lock、unseen count和reveal offset；
- `run-activity.ts`：waiting/thinking/responding/tool/retry/compaction/queued/host-loss reducer；
- `search-filter.ts`：name/provider/id ranking与fuzzy matching；
- `conversation.ts`中的stable history/tool folding投影；
- `extension_ui.v1`的Host broker、lease和typed response lifecycle。

因此 V0.2 不是把现有 `pi-tui` API复制到本仓库，而是让新的 terminal primitives直接承载这些 Dock-owned规格。

## 4. OpenClaw 固定 commit 审计

审计对象：OpenClaw commit [`d139c0e854a3c11f6ac904b34f58ad1f3dd3029b`](https://github.com/openclaw/openclaw/tree/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b)。

结论：OpenClaw对 **runtime/backend ownership** 有可参考的分层，但并未拥有完整独立 renderer，不能把它的 `terminal-core` 名称当作已经消除 `pi-tui` 耦合的证据。

证据：

- OpenClaw文档明确声明自有 built-in runtime和本地目录边界，同时明确 `pi-tui` 仍是第三方 TUI/tool renderer依赖，internalizing需要另一次 vendoring工作：[`docs/agent-runtime-architecture.md#L6-L25`](https://github.com/openclaw/openclaw/blob/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b/docs/agent-runtime-architecture.md#L6-L25)。
- TUI定义了 transport-agnostic `TuiBackend`，覆盖连接事件、chat、abort、history、sessions和models：[`src/tui/tui-backend.ts#L173-L205`](https://github.com/openclaw/openclaw/blob/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b/src/tui/tui-backend.ts#L173-L205)。该合同分别由 embedded backend和Gateway client实现：[`embedded-backend.ts#L305-L357`](https://github.com/openclaw/openclaw/blob/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b/src/tui/embedded-backend.ts#L305-L357)、[`gateway-chat.ts#L124-L169`](https://github.com/openclaw/openclaw/blob/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b/src/tui/gateway-chat.ts#L124-L169)。这证明它解决了backend切换和runtime ownership，不证明renderer独立。
- 根 package仍直接 pin `@earendil-works/pi-tui@0.80.3`：[`package.json#L2010-L2017`](https://github.com/openclaw/openclaw/blob/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b/package.json#L2010-L2017)。主 TUI仍直接导入 `ProcessTerminal`、`TUI`、`Container`、`Text`等：[`src/tui/tui.ts#L6-L15`](https://github.com/openclaw/openclaw/blob/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b/src/tui/tui.ts#L6-L15)。
- 自定义 editor只是继承 `pi-tui` `Editor`并叠加按键：[`src/tui/components/custom-editor.ts#L1-L46`](https://github.com/openclaw/openclaw/blob/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b/src/tui/components/custom-editor.ts#L1-L46)；tool renderer也直接使用 `Box/Container/Markdown/Text`：[`src/tui/components/tool-execution.ts#L1-L5`](https://github.com/openclaw/openclaw/blob/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b/src/tui/components/tool-execution.ts#L1-L5)。
- `packages/terminal-core`的公开 barrel标注为 shared terminal formatting helpers，导出 ANSI、style、progress、safe stream、table和link helpers，没有 screen buffer、diff renderer、focus tree或editor：[`packages/terminal-core/src/index.ts#L1-L19`](https://github.com/openclaw/openclaw/blob/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b/packages/terminal-core/src/index.ts#L1-L19)。其 package exports/dependencies也对应这些helper和Clack prompts，而非完整TUI engine：[`packages/terminal-core/package.json#L1-L107`](https://github.com/openclaw/openclaw/blob/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b/packages/terminal-core/package.json#L1-L107)。

对 Alu Dock 的可采纳部分只有两点：

1. backend/runtime合同与renderer合同分离；Alu Dock现有 Host/V2边界已经比该参考更严格，不需要复制其 backend。
2. 终端ANSI和safe stream helper应记录清晰provenance；例如OpenClaw自己的ANSI实现保留了源自 `ansi-regex`/`strip-ansi` 的MIT声明：[`packages/terminal-core/src/ansi.ts#L1-L32`](https://github.com/openclaw/openclaw/blob/d139c0e854a3c11f6ac904b34f58ad1f3dd3029b/packages/terminal-core/src/ansi.ts#L1-L32)。

不采纳 OpenClaw embedded runtime、Gateway protocol、session模型、component hierarchy或直接 `pi-tui` wrapper；这些都与 Dock Host唯一owner和closed V2 DTO边界无关。

## 5. 冻结的 Core API 与模块边界

建议实现目录为 `src/terminal/*`。以下是产品级最小合同；允许在实现中细化文件，但不得把runtime或wire类型带入。

### 5.1 Driver 与输入

```ts
export interface TerminalSize { columns: number; rows: number }

export interface TerminalDriver {
  readonly size: TerminalSize;
  enter(): void;
  leave(): void;
  write(frame: string): boolean;
  onInput(listener: (chunk: Uint8Array) => void): () => void;
  onResize(listener: (size: TerminalSize) => void): () => void;
}

export type InputEvent =
  | { kind: "text"; text: string }
  | { kind: "key"; key: Key; modifiers: Modifiers; phase: "press" | "repeat" | "release" }
  | { kind: "paste"; text: string }
  | { kind: "focus"; focused: boolean };

export interface InputDecoder {
  push(chunk: Uint8Array): readonly InputEvent[];
  flushEscape(): readonly InputEvent[];
  reset(): void;
}
```

`enter/leave`成对拥有 raw mode、alternate/synchronized output、bracketed paste、cursor visibility和signal cleanup。decoder覆盖标准escape、Dock需要的Kitty keyboard子集、UTF-8分片和bounded paste；未知序列不得作为可执行control text泄漏给组件。

### 5.2 Cells、width 与 differential renderer

```ts
export interface Cell { grapheme: string; width: 0 | 1 | 2; style: Style }
export interface Rect { x: number; y: number; width: number; height: number }

export interface ScreenBuffer {
  readonly width: number;
  readonly height: number;
  clear(style?: Style): void;
  writeText(x: number, y: number, text: string, style: Style, clip: Rect): void;
}

export interface ScreenRenderer {
  commit(next: ScreenBuffer, cursor?: Cursor): string;
  invalidate(): void;
}
```

Core负责grapheme segmentation、combining marks、East Asian width、emoji/ZWJ、ANSI-safe truncate/wrap和terminal rows。renderer只比较前后完整buffer，输出bounded cursor/style changes；resize强制invalidate。禁止把原始ANSI内容直接当作cell width。

### 5.3 Component、layout、focus 与 overlay

```ts
export interface Component {
  measure(constraints: Constraints): Size;
  render(target: ScreenBuffer, rect: Rect, context: RenderContext): void;
  handle?(event: InputEvent, context: InputContext): boolean;
}

export interface Focusable {
  readonly focusId: string;
  setFocused(focused: boolean): void;
}
```

最小组件集：`Text`、`VStack`、`Viewport`、`OverlayStack`、`SelectList`、`Activity`、`EditorView`、`MarkdownView`、`DiffView`和`GenericToolView`。布局每帧由terminal size和composer measure计算，不保留append-only screen assumptions。Overlay stack拥有明确z-order、modal focus save/restore和resize remeasure；extension dialog关闭后必须回到composer。

### 5.4 Editor 与 autocomplete

Editor分为纯 `EditorModel` 和渲染/输入 `EditorView`：

- multiline buffer、grapheme cursor、selection、wrap、history和undo边界；
- bracketed paste保持换行，不逐key触发command；
- Enter、Alt+Enter、Esc、Ctrl+C/D/O、PageUp/PageDown、Ctrl+End等先映射为Dock action，再由当前focus消费；
- autocomplete只接受Dock-owned `Suggestion` DTO，支持动态slash/path catalog、replace range和取消；
- IME/plain text不得被slash/action keymap误吞。

Core不理解prompt、delivery mode、setting、model或interaction response；这些仍由 `dock-tui.ts`编排。

### 5.5 Markdown、diff 与 tools

Markdown renderer只实现日常研发所需的heading、paragraph、emphasis、list、quote、link、inline/fenced code和horizontal rule。代码highlight为可选纯函数；无法安全解析时退化为原文，不发送网络请求。

Diff和generic tool view只消费Dock projection。tool默认折叠、running/succeeded/failed summary、recent/all toggle和layout-only reveal必须继续由现有deterministic specs约束，不从tool handler或runtime object读取额外数据。

## 6. Provenance 政策

默认使用clean-room实现：以本设计、现有Dock reducer tests、PTY observable behavior和公开terminal标准为输入，不逐文件翻译 `pi-tui` 或OpenClaw。

如确需采用或改写第三方MIT源码，必须在同一变更中：

1. 记录origin repository、exact commit/tag或npm tarball integrity、原始文件和GitHub permalink；
2. 在改写文件保留适用copyright/license header；
3. 将完整许可和修改说明加入 `THIRD_PARTY_NOTICES.md`；
4. 记录保留/删除的行为，尤其Unicode width、ANSI parser、key decoder和diff算法；
5. 用Dock自己的behavioral tests验证，不复制上游snapshot作为唯一证据。

禁止从安装后的 `node_modules`、npm cache或私有subpath无记录复制；禁止patch这些目录。OpenClaw仅是固定commit参考，不是隐式来源。若来源许可证、commit或改写范围不能明确，停止采用并自行实现。

## 7. 一次性切换计划

### Phase A：characterization

- 保持V0.1 renderer不变，为现有8个source import和2个test import建立本文件中的完整盘点；
- 把fixed composer、scroll lock、unseen、tool reveal、activity、search、overlay focus、confirm default No、replacement reacquire继续固化为纯spec和PTY场景；
- 采集常见SSH terminal尺寸、UTF-8/emoji/宽字符、multiline paste和resize golden行为。

### Phase B：test-only Core construction

- 在 `src/terminal/*` 实现driver/input、cells/width、renderer、component/focus、editor和text组件；
- 用独立unit/property/PTY harness测试，不在正式CLI加入renderer feature flag；
- 可以在开发分支并存代码，但不可发布双renderer，也不可让Host/protocol识别renderer版本。

### Phase C：atomic application cutover

一个聚焦切换删除所有10处直接import，并同时：

1. `dock-tui.ts`和`select-instance.ts`改用新driver/renderer；
2. `pi-tui-screen.ts`删除或改名为不含compatibility API的Core composition；
3. conversation、searchable picker、extension dialog、theme和autocomplete改用Core/Dock types；
4. 删除 `package.json`直接dependency并刷新lockfile；
5. 测试不得再import `pi-tui` helper；
6. 不保留`PiTui*` alias、adapter、环境开关或fallback。

### Phase D：完整 gate 与 immutable rollout

只有以下全部通过后才能合入并发布：

- clean TypeScript build、full tests、audit和diff checks；
- unit/property coverage：UTF-8分片、grapheme width、ANSI sanitation、cell diff、resize、focus、paste、editor history；
- 真实PTY：fixed composer、multiline增长、scroll lock/unseen、tool fold/reveal、activity、search/autocomplete、四类extension overlay、confirm No、resize、abort/detach、transport loss；
- 长SSH dogfood：连续tool/Markdown流、窄宽终端、resize风暴、断开和reattach；
- immutable release、真实resource smoke、active-instance admission和完整rollback。

## 9. 主要风险与停止条件

- **Unicode/cell错误**：若宽字符、combining或emoji导致cursor漂移，不能靠padding特例发布；必须修复width/cell模型。
- **终端清理失败**：signal、throw、transport loss后任一raw mode/cursor/paste状态不能恢复即阻断发布。
- **input歧义**：Esc timeout、Kitty release、AltGr、bracketed paste若会触发危险Dock action，必须fail closed。
- **性能退化**：长history只渲染viewport；full redraw或diff在持续stream下出现明显输入延迟即阻断发布。
- **范围膨胀**：不借迁移加入image renderer、component transport、browser UI或新的session/runtime能力。
- **provenance不清**：无法给出准确来源、license和permalink的代码不得进入Core。

该设计在V0.1只作为#148实施合同。Stage 5 durable catalog/reopen与Stage 6 session tree工作不得顺手启动renderer迁移。
