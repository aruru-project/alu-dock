# 规划与自动推进目标

Pi Worker 自动加载这项能力，不需要安装额外插件。Desktop、Android 和 TUI 复用同一套命令、状态、计划编辑和确认对话框。

## 先规划，再执行

- `/plan on 需求`：进入规划并开始调查；省略需求时只切换模式
- `/plan show`：查看完整计划
- `/plan edit`：直接编辑计划
- `/plan apply`：审阅并确认当前版本，然后开始一次正常执行
- `/plan off`：退出规划，不自动恢复已经暂停的目标

规划时，Agent 可以查项目、通过 `plan_question` 问影响方向的问题，并用 `plan_update` 保存方案。内置 read、grep、find、ls 与工具搜索可用；MCP 或自定义工具必须明确声明 `readOnlyHint: true` 才能在规划时执行。工具搜索可以发现延迟加载的只读工具。执行层同样检查通过 `ctx.executeTool` 发起的嵌套调用。

普通 shell、写文件、发送消息、部署和没有明确只读声明的工具会被拦截。原始 codemode 脚本也不会在规划阶段执行。这是模型工具入口的约束，不是操作系统沙箱；已安装扩展自己的代码仍具有 Worker 的普通权限，工具声明也需要可信。

模型不能批准自己的计划。确认过程中计划变化，旧确认不会生效。批准时会先结束仍在进行的规划回复，再把批准的计划交给执行，避免旧回复的工具调用继承新权限。长计划通过完整编辑器审阅，再作版本绑定的确认，不会只显示截断开头却批准全部内容。

`/plan on` 与执行中修改计划会停下原活动。普通实现细节不需要逐步重复批准；改变目标、授权或重要取舍时再回到用户。Plan 自己不会开启 Goal。

## 直接设置目标

例如：

```text
/goal start --rounds 10 --minutes 30 修到这组测试通过；不提交、不部署
```

可以跳过正式规划。目标包含完成条件和范围约束；Goal 不提高既有工具权限，也不替代提交、部署或付款的授权。

- `/goal status`：查看目标、预算和最新结果
- `/goal pause`：保存暂停状态并中止当前目标活动
- `/goal resume`：明确继续，沿用原目标及剩余预算
- `/goal cancel`：结束目标；会话、文件和已有结果保留

默认预算是 **10 轮目标推进、30 分钟墙钟期限**。第一轮计入10轮；同轮工具调用产生的模型往返和 Pi 原有的有限重试不另算目标轮数。轮数在活动实际开始时记账，只有待执行提议不消耗轮数。时间从目标创建算起，包含暂停和离线时间，截止后会中止当前可取消的 Pi 活动；不会承诺第三方服务或不可取消进程立刻停止收费。预算用尽后，必须由用户明确设置新的目标和预算，模型不能自行加预算。

普通补充仍通过 Queue/steer 优先进入同一份工作，不另开循环，也不要求每次补充后手动恢复。已经暂停、受阻或完成的 Goal 不会因为普通聊天被重新开启。现有“中止当前回复”同样暂停自动推进；Stop Work 仍永久结束该 Work。

Goal 只在 Pi 的 pre-settle 边界请求下一轮；重试、压缩和正常工具循环仍归 Pi。模型用 `goal_update` 记录进展、阻塞或完成。连续几轮只重复原回复、没有新的文字进展或成功工具结果时会停下来，避免空转。异步子任务继续使用已有等待/结果工具；不会为每个任务固定追加一个评审模型。

## 完成与恢复

`goal_update complete` 必须附上具体依据；界面显示模型的交付与证据。它不等于插件重新运行了检查，也不等于用户亲自验收。可验证任务有充分检查结果时可以直接交付；需要用户选择、权限或体验判断时应报告受阻并停下来。

计划和目标保存在 Pi 原生 Session 的自定义记录里，从当前分支重建，不另建 Host 业务数据库。客户端断开不影响已授权工作。Worker 重启、reload、resume、fork 或 tree 切换保留选中分支的内容和已消耗预算，自动执行默认暂停，需要 `/goal resume`。旧分支的状态不会串入当前分支。

遵循 Pi 原生持久化：全新空会话仅切换模式或编辑元数据，在出现首条用户或助手消息前还没有耐崩溃的 Session 文件。开始正常对话后，计划与目标记录随 Session 保存。自动目标一旦开始产生对话，其状态和预算可正常恢复。

## 验证边界

`test/pi-plan-goal-real.test.ts` 通过真实 DockClient、Host、独立 Worker 和 Pi，只有本机 HTTP provider 使用脚本响应。覆盖规划保护、嵌套调用、修订审批、续轮预算、暂停/中止、新输入和分支恢复。测试隔离用户配置和凭据，不调用真实模型，不安装或起停 managed service。界面能力沿现有 Extension UI；原生移动端/桌面实机体验不能由协议测试替代。
