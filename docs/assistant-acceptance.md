## 实际用起来的结果

助手自己查资料、处理日常业务、验看并交付已有文件；长时间施工仍交给 Work。公开产品只带通用接口和基础能力，私人业务模块及凭据没有进入仓库。

最后一轮使用隔离 Docker、真实 Main/Host/Worker、用户授权的 Luna/Terra 小模型，以及真正的 Linux 官方 Desktop。Desktop 由 WebKitWebDriver + Xvfb 驱动，不是浏览器 fixture。容器没有另装用户的 Pi 扩展。

## 实看发现并修正的事

- Reload 会清掉客户端的状态，之前只补回扩展状态，导致 Dock tools 明明可用却显示 OFF。现在启动和 Reload 共用一次状态重发，恢复 Dock tools、滚动整理和各扩展状态。同一条真实 Worker 回归在修复前失败，修复后通过；Desktop 也确认恢复为 ON。
- 模型曾在已成功发布文件后自行拼出 `sandbox:` 链接。工具结果现在明确说明：这是 Work 文件列表中的下载条目，不是 URL，不应编造链接。再次实测，回复改为从此 Work 的文件列表下载文件。这个指导不等于保证所有模型今后都不会误述。

## 保留的边界和取舍

- 本机扩展是用户主动信任的 JavaScript，不是沙箱。没有扫描、自动安装或 Pi 扩展兼容宿主。配置只交给本项扩展，不自动拼入模型对话；扩展作者仍须对自身输出和报错负责。
- 随包联网复用固定 `pi-web-access@0.40.0` 的公开独立入口，而非另造搜索实现。代价是增加约 200 项传递依赖；没有借此升级原有锁定依赖。外部搜索服务的可用性、权限和收费不由 Dock 保证。
- 联网独立入口不含 Pi 专属登录复用、curator、网页问答和视频等能力。搜索结果编号是临时的，扩展重载后不能当永久引用。具体配置和限制见[助手工具扩展](agent/assistant-tool-extensions.md)。
- 已有人设不被新出厂指导覆盖；名字也不从人设正文猜。人设/手写设定和完整交接提示词仍由用户编辑。
- 整理沿用当前聊天模型。手填保留量超出当前预算时只调整实际执行目标，不改保存值，并在状态中说明。首次读不到设置不猜提示词，保留完整对话继续聊；有有效旧配置时沿用并提示。
- 私人适配器是单独交付物，复用原业务模块、权限和删除确认。更新原业务后需要重新生成；它没有被写进公开 Dock，也没有在用户当前运行的 Dock 上登记或启用。
- 真实模型试验只用于本次验收，不进入日常回归或 CI。测试容器和临时凭据在完成后清理；不改动用户原服务或 Pi 扩展。真实业务验收只读，任务卡的进度另按正常流程同步。

界面验收通过临时浏览器/native 边界桥连接真实 Host/Worker；Rust 的操作接管与断线出口另有实际 core 测试。它不等于 Tauri IPC、Windows/Android 真机或本轮原生 Docker 验收。后台整理使用本地确定性模型应答和错误，不计作真实供应商验收；真实供应商只用于上述看板与日报短流程。临时凭据随隔离运行目录清理；必要的会话与业务证据只在私有验收目录保留，不进入公开仓库。

### 同日补充：扩展 models 接入与 Codex 额度查询

- **通用扩展入口**：真实隔离 Main 模型服务独占测试凭据，助手的命令与模型工具分别查询另一个通道；当前聊天模型保持不变，直接命令不触发推理，也不创建普通 Work。该回归修复前因缺少 `context.models` 失败，修复后通过；通知、工具说明和会话中没有凭据。

- **真实客户端查询**：通过浏览器边界桥连接隔离 Main/助手，使用 Main 现有且仍有效的登录快照，命令取得官方服务的真实订阅窗口、重置时间和 Credits；当前选择的是非 Codex 聊天模型。首次因隔离环境缺少现用代理失败，补齐后重验成功。登录快照未变，也没有模型推理请求。390px 窄屏实际看过结果，停用/启用并 Reload 后，命令、工具和 Skill 正确移除/恢复且无重复。
- **聊天入口**：真实助手 Worker 的工具调用、额度结果回传和后续解释用本地确定性模型应答验证，本次没有增加付费聊天模型验收。

本次增量的 `check`、完整 `npm test`、`test:client-protocol` 通过，相关扩展命令和加载回归也通过。客户端源码未改；新增功能的浏览器实看不替代 Tauri IPC 或设备验收。私有扩展和业务证据独立交付，生产尚未安装或登记；隔离登录副本随测试目录清理。

## 2026-11-17：审查整改与压缩状态修复

前一日的全门未覆盖模型服务恢复慢和扩展抛出带认证异常的故障条件。独立审查复现后暂缓合并，本轮分别修复；随后用户报告压缩后仍有新工具执行却一直显示 idle，现场只读取证，复现与修改全部放在隔离环境。

- **压缩后状态**：真实父 Work 消息启动无 Dock commandId 的 Pi run，SDK 在工具轮之间进行 threshold 压缩。旧实现把它误写成 idle；修后 status、list、重连都保持 running，watch 等实际结束后通知，忙中消息到达下一次请求。另用延迟状态提交验证采用事件到达时的事实，而非稍后的运行状态；手动压缩、中止和脱离客户端的既有回归通过。
- **查看设置和模型**：隔离模型服务被终止、替代进程未就绪时，设置立即使用已知速度支持；模型读取达到原期限后只返回 `query_timeout`，原 Pi/助手 Worker、会话与工具心跳保留。随后可中止本轮、恢复后重读模型、在同 Work 继续回复并正常 Stop。真实浏览器也看到了准确的读取超时说明，并在服务恢复后用原面板重试成功。支持变化仍沿既有通知与设置读取传播；开着的速度表单更新可选档位，未保存的 Fast/作用范围保持，未改变实际速度。
- **扩展认证异常**：Main-only 合成令牌经公开 `getAuth` 进入扩展，原工厂、命令、工具和 dispose 异常分别复现日志或模型上下文泄漏。修后这些异常转换为安全说明，日志、下一次模型请求和保存会话中均没有令牌；正常结果、中止和 Reload 行为保留。没有读取生产认证。
- **命令可达与错误归属**：真实 PTY 验证本地保留名冲突只拒该命令，`/new-echo` 等前缀不同的合法扩展命令可执行，既有本地操作与 detach 保留。App 回归与真实浏览器验证命令失败只留命令中心，切 Work 再返回仍可查看，聊天无副本；中止失败的浏览器故障注入位于 native 边界，重试则到达真实 Host。独立复审追加修正了交给 Agent 后吞错、跨 Host 迟到成功、旧运行回收及 SubHost 暂时离线误删，相关 App 红绿回归通过。

本轮 `check`、完整 `client:check` 和原生 `test:client-protocol` 通过。**完整 `npm test` 尚未放行**：远端能力回退用例出现已列出 Work 却读不到的失败，单独重跑通过；受控放慢 Main 已有状态读取后可重现同样的 `not_found`。master 也存在列表与路由映射发布不一致的窗口，这部分尚未修改，等待确认是否纳入本轮范围，不记为“基线例外通过”。
