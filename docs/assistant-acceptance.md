# 独立助手：合并前验收记录

2026-11-13。本记录保存常驻助手、独立循环、直接工具、客户端入口和后台滚动整理的合并前验证。验收期间没有安装本机版本或重启用户的 managed service；之后的发布状态以 Git tag 和发行页为准。

## 实际用起来的结果

助手自己查资料、处理日常业务、验看并交付已有文件；长时间施工仍交给 Work。公开产品只带通用接口和基础能力，私人业务模块及凭据没有进入仓库。

最后一轮使用隔离 Docker、真实 Main/Host/Worker、用户授权的 Luna/Terra 小模型，以及真正的 Linux 官方 Desktop。Desktop 由 WebKitWebDriver + Xvfb 驱动，不是浏览器 fixture。容器没有另装用户的 Pi 扩展。

| 用户动作 | 观察到的结果 |
|---|---|
| 自定义名字和人设 | 助手以“小满”回复，工作列表和设置入口使用自定义名字。 |
| 直接读取私人业务 | 调用私人工具取得正式服务中的验收卡。验收入口只允许读指定卡，不能修改正式服务；没有创建子 Work。读写业务另在回环测试服务中验证。 |
| 直接联网 | 使用随包 `web_search` 找到 Node.js 24 的官方发布说明并回答出处；不需要另开 Work。搜索、抓正文、按结果编号续读的完整工具链另用真实 Worker + 回环服务验证。 |
| 验看并交付文件 | 先读已有文本，再 `dock_deliver_file`。官方客户端的“文件”栏出现条目，Protocol 下载字节与原文一致。没有把 API 下载冒充原生保存对话框的操作验收。 |
| 在设置中禁用、重新启用扩展 | 保存不改变当时已注册工具；Reload 后工具分别消失、恢复，聊天保留。 |
| 在设置中编辑滚动整理 | 在真实 Desktop 填入启动 14000 token、保留约 1500 token 和完整自定义提示词，保存成功。 |
| 后台整理时继续聊天 | 状态显示“正在后台整理”时发送下一句话，约 12ms 获得接纳，正常得到回复。完成的交接记录采用界面保存的提示词，只留下未了结事项和限制。 |
| 整理后继续原来的事 | 正确回答仍待比较的虚构设计，以及尚需用户确认的时间；没有擅自设提醒或记入长期记忆。 |
| 重启隔离 Host | 同一个常驻助手恢复；自定义名字、聊天模型、整理参数、提示词和上次成功状态保留。 |

本轮之前，已经用真实模型/Host、Work TUI、官方 Desktop 验过聊天、记忆、派活期间继续回应、子 Work 问答、停止、提醒、遗忘、跨机器协作和后台交接；没有把这些全部再跑一遍。

## 实看发现并修正的事

- Reload 会清掉客户端的状态，之前只补回扩展状态，导致 Dock tools 明明可用却显示 OFF。现在启动和 Reload 共用一次状态重发，恢复 Dock tools、滚动整理和各扩展状态。同一条真实 Worker 回归在修复前失败，修复后通过；Desktop 也确认恢复为 ON。
- 模型曾在已成功发布文件后自行拼出 `sandbox:` 链接。工具结果现在明确说明：这是 Work 文件列表中的下载条目，不是 URL，不应编造链接。再次实测，回复改为从此 Work 的文件列表下载文件。这个指导不等于保证所有模型今后都不会误述。

## 普通验证与代码审查

- 最后一次全量 Node 验证跑了 462 项。发现两处仍期待旧设置形状/旧送达默认值的断言、一处把模型收到请求当成 Host 已收到队列变化的观察时序问题，已分别调整并定向通过。另三处失败来自试验目录缺少真实打包输入/用软链代替源码目录，在真实源码目录重跑相关打包验证后通过。
- 最后修复后没有再次跑整套 Node 测试；补跑了受影响的扩展 Reload、Dock 工具等定向回环，不用重复全量次数充当验收。
- `npm run client:check` 通过，包括前端、Rust 和构建；Linux Desktop 实际构建成功。
- Pi SDK 兼容门通过。官方 Rust 客户端的 Protocol 门通过；其中一处仍期待“目录可默认创建新助手”的旧断言已按唯一常驻语义更新并复核。
- 整分支此前做过独立只读审查；最后的扩展、联网和收尾增量另做一次独立只读审查，没有发现阻塞。只读审查不等于另做了一遍运行验收。
- 本轮没有实际运行 Windows 或 Android 客户端；不能将 Rust/前端检查说成这两个平台的实机验收。

## 保留的边界和取舍

- 本机扩展是用户主动信任的 JavaScript，不是沙箱。没有扫描、自动安装或 Pi 扩展兼容宿主。配置只交给本项扩展，不自动拼入模型对话；扩展作者仍须对自身输出和报错负责。
- 随包联网复用固定 `pi-web-access@0.40.0` 的公开独立入口，而非另造搜索实现。代价是增加约 200 项传递依赖；没有借此升级原有锁定依赖。外部搜索服务的可用性、权限和收费不由 Dock 保证。
- 联网独立入口不含 Pi 专属登录复用、curator、网页问答和视频等能力。搜索结果编号是临时的，扩展重载后不能当永久引用。具体配置和限制见[助手工具扩展](agent/assistant-tool-extensions.md)。
- 已有人设不被新出厂指导覆盖；名字也不从人设正文猜。人设/手写设定和完整交接提示词仍由用户编辑。
- 整理沿用当前聊天模型。手填保留量超出当前预算时只调整实际执行目标，不改保存值，并在状态中说明。首次读不到设置不猜提示词，保留完整对话继续聊；有有效旧配置时沿用并提示。
- 私人适配器是单独交付物，复用原业务模块、权限和删除确认。更新原业务后需要重新生成；它没有被写进公开 Dock，也没有在用户当前运行的 Dock 上登记或启用。
- 真实模型试验只用于本次验收，不进入日常回归或 CI。测试容器和临时凭据在完成后清理；不改动用户原服务或 Pi 扩展。真实业务验收只读，任务卡的进度另按正常流程同步。
